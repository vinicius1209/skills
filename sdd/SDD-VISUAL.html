Tiered Adoption

Don't boil the ocean. Start at the tier that matches your project and grow as needed.

🌱

MVP SDD

Solo dev or small project, new codebase. ~30 min setup.

  • Agents: architect, dev, code-review
  • Commands: /feature, /prd, /spec, /developer, /pr
  • Skills: 1 domain skill (SKILL.md only)
  • References: architecture.md, shared-ui-inventory.md
  • Hooks: auto-commit-plans.sh
🛡️

Quality SDD

Small team, production project. Adds safety nets.

  • Agents: + tester, dba
  • Commands: + /test-suite
  • Skills: + references/ subfolder
  • References: + forms.md, dialogs.md, query-patterns.md, navigation-surfaces.md
  • Hooks: + check-pr-state.sh, verify-deliverables.sh, detect-stale-plans.sh
🏭

Full SDD

Team, complex domain, CI/CD. Full lifecycle.

  • Agents: + qa-smoke
  • Commands: + /plan-sync, /release, /nightly-tests, /annotate, /review
  • Plans: + nightly-tests/ coverage tracker
  • Hooks: + log-session-metrics.sh, domain-specific hooks
  • Processes: Release audit gates, doc-debt detection

Core Concepts

The six pillars that make Spec-Driven Development work.

🤖

Agents

Your AI Team. Specialized roles with scoped permissions.

  • Read-only agents can't break prod
  • Write-scoped agents stay in their lane
  • Failure modes act as institutional memory
🧠

Skills

Injectable domain knowledge. The highest-leverage artifact.

  • Inviolable business rules
  • Canonical vocabulary
  • Schema gotchas and traps
⚡

Commands

The Pipeline. Slash commands that orchestrate the flow.

  • /feature runs all stages
  • Each command updates the manifest
  • Context is cleared between stages
📜

Plans & Manifest

The Contract. Tracks lifecycle and artifacts.

  • manifest.json is the source of truth
  • Scenario Matrix forces clarity
  • Enables smart resume and verification
📚

References

Canonical Patterns. Prevents agents from reinventing solutions.

  • Routing tables: "use this, not that"
  • Points to gold-standard files
  • Shared UI inventory is mandatory
🪝

Hooks

Automated Safety Gates. Enforce rules prompts can't.

  • Triggered on tool events
  • Block invalid actions (e.g., bad migrations)
  • Auto-stage files and log metrics

Scenario Matrix

The single most important artifact in SDD. It captures who sees what and what happens for every persona × state combination, forcing ambiguity to surface before any code is written.

Persona State / Input What they SEE in the UI What happens in the BACKEND
Admin Opens form Full edit + override controls Rule applied + logged to audit_trail
User (Seller) Opens form Read-only display of aggregated values Rule applied server-side (opaque)
Guest Attempts access Access denied screen 403 Forbidden response

When to Use SDD

SDD is powerful, but it adds ceremony. Know when to apply it.

✅ Good Fit

  • ✓
    Recurring feature work
    Not just one-off scripts.
  • ✓
    Regular AI usage
    You use agents for implementation.
  • ✓
    Complex business rules
    Agents need to respect constraints consistently.
  • ✓
    Need for auditability
    Who decided what, when, and why.

❌ Overkill

  • ✕
    Typo fixes & config tweaks
    Just do the change, no PRD needed.
  • ✕
    Prototypes / throwaway code
    SDD adds ceremony that slows exploration.
  • ✕
    Solo dev + simple domain
    If you hold it all in your head, skills are dead weight.
  • ✕
    No AI agents
    Without agents, it's just heavy process.
